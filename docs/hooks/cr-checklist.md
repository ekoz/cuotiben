# CR 检查清单

评审代码与内容改动时逐项核对。

## 代码与内容规范

- [ ] 站点内容使用中文（C-001）。
- [ ] 内容位于「学科 → 学期」目录结构内，未混放（C-002）。
- [ ] 错题条目包含六个固定字段：题目、我的答案、正确答案、错因分析、订正、复习日期（C-003）。
- [ ] 多次复习以追加方式记录，未覆盖历史复习日期（C-004）。
- [ ] 遵循 Google 编码规范（JavaScript/TypeScript 部分）；VitePress 配置保持可读、最小化。

## 架构约束

- [ ] 保持 VitePress 静态站点形态与 npm 包管理（C-005）。
- [ ] 未在未经 Spec 评审的情况下引入后端、数据库或其他新运行时依赖。
- [ ] 新增依赖有明确用途，未引入与静态站点定位冲突的运行时。

## Invariants

- [ ] 未破坏 `docs/harness/index.md` 中的已确认约束；若需求确实需要变更约束，已取得明确变更决定并同步更新 harness。
- [ ] 未把知识库中的当前行为描述擅自升级为硬规则。

## Tasks checkpoint

- [ ] 当前 feature 的 `tasks.md` 已完成项与代码改动一致。
- [ ] 未完成项有明确原因或阻塞说明。

## Verification 证据

- [ ] 构建或测试已实际执行，并在 `verify-report.md` 记录命令与结果。
- [ ] 未执行或无法执行的项目已如实标注，未声称通过。

## Finding 对账

- [ ] 评审 finding 已逐条处理：修复、说明不修理由或标记待决。
- [ ] 未通过降低已确认规约来消除 finding。
